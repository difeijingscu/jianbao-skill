# content.json 结构与写作规范

`content.json` 是简报的唯一内容来源。`build.py` 把它渲染成 HTML；改内容只改这里。

## 一、顶层结构

```json
{
  "meta": {},
  "headline": {},
  "sections": [],
  "note": "数据口径说明",
  "sources": [],
  "footer_left": "编制方 / 保密级别",
  "footer_note": "生成时间：YYYY-MM-DD HH:MM"
}
```

## 二、meta / headline

| 字段 | 说明 | 约束 |
|---|---|---|
| `meta.topic` | 主题短名，用于文件名 | ≤20 字，不带标点 |
| `meta.kicker` | 刊头行，正式/英文口径 | 全大写英文或机构名，≤40 字符；**不带 DAY 1 这类期次** |
| `meta.kicker_note` | 刊头右侧小字 | 如「内部简报 · 供高层参阅」 |
| `meta.title` | 主标题 | **按主题定名**：`<主题>：<判断或观察角度>`，≤28 字；**不写 DayN / 第N天 / 期次编号** |
| `meta.subtitle` | 副标题：这份简报回答什么问题 | 一句话，≤40 字 |
| `meta.meta_line` | 元信息数组，用 `　|　` 连接 | 3 项：范围 / 周期 / 信息截止 |
| `meta.author` | 整理方 | 单行，显示在元信息下一行 |
| `meta.date` | 交付日期 | `YYYY-MM-DD`，validate 强校验 |
| `headline.label` | 结论标签 | 默认「核心判断」 |
| `headline.text` | **一句话结论** | 90–130 字，见下方写法 |

### 命名：按主题，不按天

简报名 = **用户给的主题 + 结论/观察角度**，不是「某会议 Day3」。

| 场景 | 正确 | 错误 |
|---|---|---|
| 展会整体观察 | 智能制造装备展：整线交付成为竞争主线 | 智能制造装备展 Day2 观察简报 |
| 同一主题持续跟踪 | 同一标题，靠 `meta.date` 与文件名日期区分（`简报-AI芯片出口管制-20261105-L1-T1-商务蓝.pdf`） | AI 芯片管制简报（第 3 天） |
| 事件进展 | 某出口管制新规：执行口径出现分化 | 事件跟踪第 2 期 |

`validate.py` 的 `E19` 会拦下 `Day2 / 第 2 天 / 第 3 日 / D1` 这类写法。确有按天分期的场景（逐日跟踪的展会日报）加 `--allow-period` 放行。

正文里该出现的日期、时段照常写（「10 月 29 日下午主论坛」「首两日」），受限的只是**标题与段名**。

### headline 写法（最关键的一段）

结构固定三段，不要写成摘要：

```
发生了什么（含关键数字）→ 意味着什么（判断）→ 一句收口（<b>加粗</b>）
```

范例（结构示范，非真实事件）：

> 本届展会主线从单机性能转向产线级交付：主论坛把竞争焦点定在整线节拍与换型速度，下午六个展区集中发布产线级方案——**卖设备的时代正在让位于卖产能的时代**，采购评估口径需要同步改写。

反例（不要这样写）：
- 罗列议程（"上午 9 点开会，10 点发布…"）——这是议程表，不是结论
- 全是形容词（"成果丰硕、意义重大"）——无法验证
- 超过 150 字——高层不会读第二行以后

## 三、sections

```json
{
  "no": "01",
  "title": "核心事实与进展",
  "sub": "来源：官方新闻稿 · 已核实",
  "page": 1,
  "p": 1,
  "part": {"no": "01", "title": "事实与判断", "sub": "关键信号 · 12 场发布"},
  "blocks": []
}
```

- `page`：L1/L3 下的目标页（1 起）；L2 忽略此字段，全部压到第 1 页。
- `p`：优先级。**1** = 核心（L2 也保留）；**2** = 标准（L1 保留）；**3** = 扩展（仅 L3）。
- `part`：可选，渲染成整横幅，用来给页面分大段（一页最多 1 个）。
- `sub`：章节副标题，写**口径或来源**，不要写空话（"详见下文"这类不要）。

### 推荐骨架（可增删，保持顺序）

| 页 | 段 | p | 作用 |
|---|---|---|---|
| 1 | 核心事实与进展 | 1 | lead + metrics + list，回答"发生了什么" |
| 1 | 关键活动议程 / 关键节点 | 2 | agenda 或 table，给事实骨架 |
| 1 | 分布 / 热度 / 结构 | 2 | bars，给量的感觉 |
| 1 | 主要观点与信号 | 1 | cards，回答"各方在说什么" |
| 2 | 进展时间线 | 2 | timeline，回答"怎么走到这一步" |
| 2 | 关键量化指标 | 1 | table，可对标、可测算 |
| 2 | 对我们的影响与建议 | 1 | columns（影响 / 建议 / 待确认） |
| 2 | 横向对比 | 2 | table，选型或竞争格局 |
| 2 | 风险与不确定性 | 2 | list，每条标置信度 |
| 2 | 术语速查 | 3 | cards，供非专业读者 |

段数 3–10。少于 3 段撑不起简报，多于 10 段说明该拆成两期。

## 四、blocks 详解

### lead
```json
{"type":"lead","label":"总判断","text":"2–4 句，说清全局判断，不要复述标题"}
```

### metrics
```json
{"type":"metrics","items":[{"value":"1,850","unit":"家","label":"参展商（较上届 +12%）"}]}
```
3–4 个为宜。`label` 里括号补口径或对比基准。**这些数字必须在正文其他位置也出现**，否则 `validate.py` 会报 W4。

### list
```json
{"type":"list","ordered":true,"items":["<b>要点词</b>：一句话说明"]}
```
每条 1–2 行，前面用 `<b>` 给一个短标签（4–8 字），后面跟事实。

### cards
```json
{"type":"cards","cols":2,"items":[
  {"title":"观点标题","right":"来源 · 时间","hi":true,"text":"归纳，<b>关键结论</b>"}
]}
```
`cols` 2 或 3。`right` 写来源与场合（"主论坛 · 09:40"），是可核查性的最小成本。`hi:true` 只给 1–2 张最重要的卡。

### columns
```json
{"type":"columns","items":[
  {"title":"影响","sub":"IMPACT","items":["…"]},
  {"title":"建议","sub":"ACTION","items":["…"]},
  {"title":"待确认","sub":"OPEN","items":["…"]}
]}
```
建议写成**可执行动作**（动词开头 + 对象 + 时间），不写"加强重视"这类口号。

### table
```json
{"type":"table","head":["指标项","公开口径","业务含义"],
 "widths":["34mm","52mm",""],"rows":[["整线节拍","<b>42 秒/件</b>","…"]]}
```
`widths` 与 `head` 等长，最后一列留空自适应。数值列用 `<b>`，业务含义列写"对决策意味着什么"。

### agenda
```json
{"type":"agenda","head":["时间","场次 / 主讲","核心内容"],
 "widths":["20mm","44mm"],"rows":[["09:40–10:10","主论坛 · 某某","…"]]}
```
三列固定：时间 / 主体 / 内容。`widths` 只给前两列。

### bars
```json
{"type":"bars","items":[{"label":"工业机器人","value":412,"pct":100,"unit":" 场洽谈","hi":true}]}
```
`pct` 是条形长度（0–100，最大项给 100），`value` 是显示数值。`unit` 前留一个空格。`hi` 给前 2 项。

### timeline
```json
{"type":"timeline","items":[
  {"date":"10.29","phase":"当前","tag":"转向","hi":true,
   "stat":"整线交付成主线 · <b>12</b> 场发布","desc":"…","items":["子事实"]}
]}
```
3–5 个节点。`hi` 标当前节点。`phase` 是**阶段词**（前期 / 当前 / 后续 / 布展 / 收尾），
不是「第 N 天」——写绝对日期或阶段，别写 DayN。（旧字段名 `week` 仍兼容，新内容用 `phase`。）

## 五、note 与 sources

`note`（数据口径说明）必须写清三件事：
1. 每个数字的来源与统计口径；
2. 哪些是厂商/当事方口径、未经第三方验证；
3. 哪些是推断、哪些已核实。

`sources` 至少 3 条，字段 `publisher / title / date / url`。`date` 缺失会报 W2——时效信息必须可追溯。

## 六、写作语气

- 先结论后论据，一句话能说清的不写两句。
- 名词用当事方官方口径，不改写、不去掉限定语（"计划""预计""宣称"这类词要保留）。
- 不用形容词堆砌（"重磅""颠覆性""历史性"），用数字和对比代替。
- 不确定就写不确定：`（待确认）`、`（置信度：中）`。
